# TwoKit 2.0: working notes for Claude

TwoKit is a design-system generator (colors, surfaces, text colors, fluid type and spacing, a small set of utility classes). One source, three products:

- **Web app**: `app/` (vanilla ES modules, no build). Serve with `python -m http.server 5178` from `app/` (launch config "twokit").
- **WordPress plugin** (Bricks): `plugins/wordpress/` (PHP) + the app bundle.
- **Figma plugin**: `plugins/figma/` (sandbox + host) + the app bundle.

**Repo**: https://github.com/MahmudZar/Twokitbeta (public, branch `main`; this folder is the checkout, push over HTTPS). Live web app: https://twokit.netlify.app/ (`netlify.toml` publishes `app/`). Third-party code, old versions and exports stay local (`.gitignore`).

Build both plugins: `npm install` once, then `npm run build` → `dist/` (+ the latest zip of each plugin; older zips move to `dist/archive/`). See `docs/plugins-plan.md` for the full architecture, security model and test steps. **Keep that file and this one updated with every change.**

## Rules the user set (do not break)

- The plugins **are the web app**: same UI, same previews. Don't invent screens, panels, specimens, stats or settings the web app doesn't have. No fluff. The Example site preview is hidden in the plugins.
- Anything Bricks can hold is written into Bricks. Fonts always go to the **Bricks font library**; TwoKit never hosts fonts; Bricks' Google Fonts loading is off.
- **No JavaScript on the site.** Light/dark = Bricks `data-brx-theme` + Style manager. (The builder variable picker is builder-only: Bricks builder main window, logged-in editors. Never the site or the canvas.)
- **Builder variable picker = minimal, like Core Framework's**: search + close in the header, accordions per TwoKit category, plain chips. Visuals only for colors (light/dark pairs, palettes: base bar + shades + tints) and grids. No hint footers, no recent row, no scope toggles, no pin. States and button variants as tabs. Design: Figma section "TwoKit Variable Picker v3".
- **No Figma ↔ WordPress connection.** Exports only (HTML & CSS, Bricks zip, Figma package).
- WordPress setup = **one screen** (TwoKit files vs Saved in Bricks), then the app. Figma has no setup, it has **Apply to Figma**.
- Closed-mode CSS is **minified** (`core/minifyCss.js`).
- Surface, text, action and hover colors are **derived** from the surface + primary colors; they are not individually editable (as in the web app).
- Every new TwoKit token must also export as a Bricks variable (systemRows/themeRows).
- Bricks palette colors are raw `var()` only.
- Line height tokens: only `--heading-line-height` / `--text-line-height`.
- Utility classes: curated and minimal; no one-property clutter.
- WordPress code: WordPress Coding Standards, prefixes `twokit_` / `TwoKit_`, text domain `twokit`, GPL-2.0-or-later, capability + nonce on every write, never unzip in TwoKit's PHP, fixed file names only, escape all output.

## How the plugins plug in

- `app/assets/js/platform.js`: `window.TWOKIT_HOST` (set by the host page) gives storage, asset URLs, embedded files and hidden features. The web app never sets it.
- `app/assets/js/hosts/wordpress.js`: setup screen, mode chip, Save (Ctrl/Cmd S) → `POST /wp-json/twokit/v1/save`.
- `app/assets/js/hosts/figma.js`: Apply to Figma → `plugins/figma/code.js` (inspect → review → import).
- `ExportModule.bricksPackage(model, { parts, skipMissingFonts, cssInBricks })` builds the same zip as Export → Bricks; PHP hands it to `\Bricks\Unified_Global_Transfer::import_package_bytes`.

## Gotchas

- Many source files use CRLF; Python/Bash edits fail on them. Use the Edit tool, or a Node script that normalizes `\r\n` (see past scripts in the scratchpad pattern).
- Bash heredocs strip backslashes; write scripts with the Write tool.
- Git Bash rewrites `/wordpress/...` arguments: prefix commands with `MSYS_NO_PATHCONV=1`.
- Browser HTTP cache keeps old modules: `fetch(url, {cache:'reload'})` then reload.
- `app/figma-plugin/` is build output (copied from `dist/figma/twokit-figma`); edit `plugins/figma/` instead.
- `node --check` works on a copy named `*.mjs`.
- Bricks builder canvas: Bricks' CSS sits in `<style>` tags inside `div.brx-body`, after `<head>`. TwoKit's closed-mode CSS must come after it (printed at `wp_footer`), as on the site. Don't use late `wp_enqueue_style` for this: WordPress 6.9+ hoists late styles into `<head>`.
- Testing the canvas without a Bricks license: load `<page>?bricks=run&brickspreview=1` directly (Bricks skips the license check for the iframe).
